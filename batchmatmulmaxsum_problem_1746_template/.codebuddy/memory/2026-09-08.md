## 六、v2 架构转向 = 「分相」（相对 plan 原案，关键修订）

- 原 plan 案（C-tile 内行归约、C 不落 GM、单 launch）**不可行**：其归约依赖 GetTensorC→vector，被 §4.1 判死为竞态。
- **v2 分相**：
  - 相①（cube）：纯 cube（F5 形态）对某 batch 整写 M×N fp32 C 到 **GM workspace**（aclrtMalloc，run_kernel 内）；
  - 相②（vector）：独立 `__aicore__` vector 核读 GM C，按 v1 kernel.asc 已验证惯用法
    （64-chunk masked DataCopyPad 读 + ReduceMax→Max 链 fold（rm[0]=-FLT_MAX）+ acc[0] count-1 Add + 4B DataCopyPad 写）
    算 `y[b]=Σ_m max_n C[m][n]`；无 bias（贴合真实接口）。
  - 排序：同一 stream 上「cube(batch b) → reduce(batch b)」顺序 launch 即保证；host 逐 batch 推进。
  - shape 门控：M<baseM 或 N<baseN 之类 tiling 拒收的 shape 回退 v1；fp16 cube 先行，bf16 cube 支持未验证（vector 兜底）。
- 依据复核：本地 main.asc/run.sh 的 `run_kernel` 是纯 host 侧驱动（可多 launch、可 aclrtMalloc、stream 现成）。

## 七、⚠️ 与判题平台「每 iteration 恰 1 launch」规则的冲突（关键未决，勿丢失）

  分相多 launch 会再次违反 profiling 规则。判题使用平台私有 host driver 调 run_kernel（GM_ADDR），**本地 main.asc 的

- shape_sweep F4 本轮 0/12 PASS（上轮 1/12）：非纯 cube 文件里 IterateAll 逐 run 抖动。M64/M16 TILING_FAIL 复现（门控边界=回退 v1 判据）。

### 11.5 cube_probe mode 修正（推翻 §4.1 的「四态同构/queue 不可修」）
- 本轮事实：mode0/2/3 逐位同构（mismatch=3072/4096；mirror 带 row0..31 全 G=32/32，即 tile(0,0) 正确；main rows0..31=G、row32=S、rows33..63=0）；
  mode1 独坏（mismatch=4064/4096；mirror G=2/P=30、main G=1/S=32/0=31）。
- **判读**：
  1. Abs 紧随 GetTensorC（无交接）→ vector 在末次 k 未落定时消费 → 全带 (K-1)/K 部分和 + 行别名指纹（P/S）——**紧随消费竞态真实存在**。
  2. GetTensorC 与 Abs 之间插入 TQue EnQue/DeQue（mode2）或仅空交接（mode3）→ 恢复 mode0 行为 —— **queue 交接 = 本栈同 TU 的同步原语**，Abs 本身无辜。
  3. 但 mode0/2/3 仍仅 tile(0,0) 对位（main rows33..63 全 0）→ 坐标解码坏与本竞态是**两个独立 bug**；
     09-07 mode0 全 G ↔ 今日仅角 tile 对 → 跨 run 不稳依旧。→ GetTensorC 通道整体不作 v2 基座。
  4. 保留给「单 launch」研究的关键事实：同 TU vector 消费 cube C 须经 TQue 交接同步（mode2 形态为样板雏形）；
     IterateAll GM 直写后**同核读回**（不经 GetTensorC、DataCopy 读 GM）无现成蓝本，需 F8 级探针另验。

### 11.6 收敛 recipe + 决策（v2 素材）
- 正确基座：单核 per batch 纯 cube（F5 形态）整写 M×N fp32 C → GM workspace；vector 归约独立核（v1 惯用法）；host 同 stream 排序。多核提速仅限 M 向 slab + off1。
