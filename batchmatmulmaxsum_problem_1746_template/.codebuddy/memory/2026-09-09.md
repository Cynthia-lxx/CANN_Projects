## 三、新根因候选（高度契合观察）— dtype 枚举语义

- 模板注释/本地 main.asc 使用自造枚举：1=fp16、2=bf16（`TensorInfo.dtype`）。
- CANN 真实 aclDataType（头库 asc/impl/utils/debug/asc_debug_types.h 与 kernel_utils_dump_constants.h）：
  `ACL_FLOAT=0, ACL_FLOAT16=1, ..., ACL_BF16=27`。
- 原 kernel.asc 判 `isBf16 = (dtypeCode == 2)`。若 judge host 用 acl 码填充 dtype，则：
  - fp16 点 dtype=1 → 走 fp16 kernel → PASS（恰好 2 个，对应点 1/5）；
  - bf16 点 dtype=27 → 被误判为 fp16 → 用 fp16 kernel 读 bf16 位型 → 大值垃圾 → WA（点 2-9）；
  - 大 bf16 点仍 TLE（点 10）、更大被 Skip（点 11-15）。
- 该假设同时解释「转置修复后结果不变」：dtype 判定代码两版相同。

## 四、修复（no-regret，零风险）

- kernel.asc run_kernel：`isBf16 = (dtypeCode != 1)`。两种编码 fp16 都 ==1；输入仅 fp16/bf16，
  「非 1 即 bf16」在模板枚举（2）与 acl 枚举（27）下都正确。
- 本地 main.asc 增 `BMM_ACL_DTYPE=1` 模拟 judge acl 码喂入（manifest dtype 2 → TensorInfo.dtype 27），
  可云验两种喂法同结果，直接证明修复覆盖面。
- gen_data_casematrix.py 增官方域用例 cid 220-233（奇小 shape + tx 组合 + 全负 + 长 K 等）。
