### 9.3 核心矛盾 & 三种互斥解释（下一步必须先分辨 H2 与 H2'）
本地验证最强的 a6c3a57（34/34 绿）提交 judge 仍逐点不变。而探针3（跳过 normalize）judge 也逐点不变。
这组结果本身无法区分以下解释：
- **H1（此前已自洽但被 a6c3a57 削弱）**：judge 禁 run_kernel 内 aclrtMalloc/aclrtMemcpy 等运行期 API。
  但矛盾点：若 tx 点在 aclrtMalloc 失败即提前 return，则该点 0 次 launch，与「每 iteration 恰 1 launch」
  冲突（除非那些 iteration 恰好都是非 tx 点）。
- **H2（新强假设）**：judge **从不设置 transposeX1/X2（恒 false / 忽略标志）**，数据始终按逻辑行优先下发。
  → 所有 normalize 分支对 judge 是 no-op → 无论怎么改 tx 代码都逐点不变。7 个 WA 点其实是非转置点，
  因别的根因（shape/dtype/数据/layout 假设…）失败；本地 34 例没有覆盖 judge 的真实失败形状。
- **H2'**：judge 标志/数据确实转置且环境正常，但 normalize 对「对称/退化」形状恰好是幂等/无害，
  只有某些特定形状才表现出差异且本地恰好没覆盖。

**判别探针（下一位 agent 建议先做，最省时）**：下一次判题用「无条件强制双转置」版 ——
把 v1 的 tx1/tx2 分支改成 `if(true)`（恒按物理 (B,K,M)/(B,N,K) gather 读），即对 judge 数据无条件做一次
逻辑归一：
- 若 judge 是 H2（数据恒逻辑、无转置）→ 现在 ff 点也被错误 gather → 原本 2 PASS 点应翻成 WA；其他点数值
  变化 → judge 结果**不再逐点不变** → H2 实锤，立即放弃转置方向，转攻 7 个 WA 的真实 shape 根因。
- 若 judge 是 H2'（数据真转置、环境正常）→ 对真 tx 点 gather 一次 = 幂等还原，结果仍正确（unchanged），

- 若 H1（环境禁 API）→ 纯核内 gather 无 API，该探针结果 = H2' 的 ff 点翻 WA 情形，需要再配合
  「flag 恒 false 但数据真转置」的变体（即恒不 gather）区分——两次探针即可完成四象限判别。

WA 的点，不影响 2 PASS 点）。若 judge 任何点出现该特征值 → 证明 judge 会设置标志；全部不出现 → H2。
